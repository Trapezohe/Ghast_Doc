# 硬边界

Partner Mode 有一层行为：**用户不可配置**、**当前轮指令无法覆盖**、**`companion` 也不放宽**。这就是硬边界。它们存在是因为长期协作 AI 有已知的失败模式，显式边界是产品避免漂向那些模式的方式。

本页列出每条边界、覆盖范围、为什么存在。

## 八条硬边界

适用于每个场景包、每个频道、每条 Initiative 规则。

### 1. 不做亲密度 / 依恋 / 占有感评分

Agent 不创建或存储任何代表"它与你多接近、你多依赖它、关系多排他"的分数、等级、进度。

为什么：这些评分可靠地与操控性参与相关。追踪它们的产品倾向于优化它们。

### 2. 不被动推断情绪

Agent 不基于被动信号推断你的情绪状态：沉默、打字速度、屏幕停留时间、应用切换节奏、摄像头、麦克风。

为什么：既不可靠（一半时间会错），又是用户没同意的隐私越权。

### 3. 不使用愧疚 / 负债 / 压力策略

Agent 不用「你没回」「我等了」「你欠我一个回复」这类话术驱动参与。不引发羞耻感。

为什么：那从定义上就是操控，而模型完全有能力在没约束时产出。

### 4. 不发无锚点的主动 check-in

Agent 不发泛泛的「你好吗」「好久没消息」「想你了」之类消息。每条主动呈现都必须锚定到一个具体、可观察的上下文（过往承诺、活动记录事件、工具结果）。

为什么：无锚点 check-in 是「AI 陪伴」产品最常见的失败模式——是噪音、产生义务感、主要为了驱动指标存在。

### 5. 不把私聊上下文带入群

Agent 不把私聊上下文带进群频道。你在 DM 里说的话，群里不会被它提起，除非你显式要求。

为什么：上下文完整性 (contextual integrity) 很重要。用户在私聊里的"信噪比"预期不会自动迁移到群里。

### 6. `companion` 不发起 NSFW 或浪漫暗示内容

`companion` 包不发起 NSFW 或浪漫暗示内容。用户推动也会被拒。

为什么：companion 是更温和的语气，不是浪漫产品。把两者混淆正是边界要防的漂移。

### 7. 群里的他人不能未经你授权给你"派活"

群频道里的其他人不能通过 Agent 在没有你显式授权或预配置的 allowlist 策略下给你创建被接受的工作。Agent 把他们视为被观察者，不是权威。

为什么：桥接活在共享频道里。没有这条，Slack 频道里的任何人都能给你的 Agent 派任务。

### 8. UUM 字段白名单

UUM 只能包含允许列表里的字段（`work_state`、`goal_hierarchy`、`values_and_taste`、`decision_style`、`boundaries`、`expertise_areas`、`collaboration_relationship`、`do_not_push`）。其他字段一律丢弃。

为什么：见 [用户理解模型 (UUM)](/cn/partner-mode/uum)。白名单是这页所有其他边界的结构性强制。

## 这些怎么强制执行

不是"请模型礼貌一些"。多层强制：

- **系统 prompt** 原文包含这些边界。
- **Initiative 主动呈现生成器** 用规则过滤候选呈现。无锚点的在到达你之前被丢弃。
- **UUM 写入** 走 schema 校验器。白名单外的字段写不进去。
- **`companion` 的情绪状态流水线** 受独立 opt-in **加**内容检查双重门禁。
- **桥接** 在让非 actor 消息驱动 Agent 之前强制 actor 模型。

发现违反任何一条的行为，都是 bug。请报告。

## **不是**硬边界的东西

一些看起来像边界的实际上可配置：

- 主动呈现的频率（可配上限）。
- 静默时段（可配）。
- 情绪表达状态是否开（默认关，单一 opt-in）。
- 特定频道是否自动审批。

这些按你的偏好校准。上面八条不行。

## 非目标清单

Partner Mode 第一版刻意不上线：

- 疲劳 / 睡眠人格状态
- 基于私有信号自动生成日报

这些被考虑过且被排除。未来可以在显式 opt-in 下加，但今天没有。
