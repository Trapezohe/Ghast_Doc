# 0G Storage 加密同步

0G Storage 同步是 Ghast 提供的可选跨设备备份方案。它在本地加密你的数据，上传到 0G 存储网络，并把内容哈希写入链上 Pointer Registry。解密密钥从你的钱包派生——Ghast 读不了你的备份。

这是除推理流量本身之外，数据离开机器的**唯一**通道。**默认关闭**，按类别 opt-in。

## UI 入口

Settings → Data → **0G Storage Sync**。面板里有：

- 主开关（默认关闭）。
- 按类别的子开关（memories、conversations、providers、prompts、skills）。
- 下次同步的计划时间。
- 「立即同步」按钮（手动触发）。
- 上次同步状态（成功 / 失败附简短原因）。

## 加密如何工作

每次上传都在数据离开机器前完成加密：

| 阶段 | 发生什么 |
| --- | --- |
| 密钥派生 | 用 HKDF-SHA256 从钱包私钥派生 AES-256-GCM 密钥 |
| 加密 | 用该密钥加密序列化后的类别快照 |
| 上传 | 密文发送到 0G 存储 indexer（`https://indexer-storage-turbo.0g.ai`） |
| 写指针 | 内容哈希签名后提交到链上 Pointer Registry 合约（chain 16661 上的 `0x68F8610...61c`） |

派生出的密钥不会落盘。密钥派生是确定性的——同一个钱包总是派生出同一个密钥——这就是为什么换设备用同一个钱包能恢复。

## 哪些数据会被备份

| 类别 | 默认状态 | 内容 |
| --- | --- | --- |
| **Memories** | 关闭 | 向量记忆记录及其 embeddings |
| **Conversations** | 关闭 | 完整的对话与工具调用 |
| **Providers** | 关闭 | 已启用的供应商配置（不包含 key 本身） |
| **Prompts** | 关闭 | 保存的提示词模板 |
| **Skills** | 关闭 | 你安装或自创的技能 |

钱包本身**不**会被同步到 0G Storage。助记词/私钥是你的责任——见 [钱包与密钥托管](/cn/web3/wallet-and-key-custody)。

## 同步什么时候发生

- **定时**——默认每天本地时间 06:00 触发（面板里可配置）。
- **手动**——「立即同步」按钮。
- **不是实时**——同步是快照式的，不是逐条变更。要在另一台设备看到最新状态，先在源设备手动同步。

## 在新设备上恢复

新机器上的流程：

1. 安装 Ghast AI Desktop。
2. 用同一个邮箱账号登录。
3. Onboarding 阶段选「用助记词导入」，输入同一个钱包的助记词。
4. Profile 创建并绑定钱包后，客户端会到链上 Pointer Registry 查找该钱包地址相关的快照。
5. 每个已备份的类别都会被拉回密文，本地用派生密钥解密，合并进本地数据库。

钱包不匹配时解密会失败。**钱包丢了没有恢复路径**——加密包还留在 0G Storage 上，但没人能读了。

## 费用

每次上传都要消耗 OG 来：注册链上指针、把密文存到存储网络。每次快照的费用很小（正常体量的 Profile 通常远小于 1 OG），但需要钱包里有 OG 余额。

## 这不是什么

- **不是实时同步**。设备 A 上 09:00 改了东西，09:05 打开设备 B，看不到变化——除非你先在 A 上触发同步。
- **不是服务器侧服务**。Ghast 没有运行一个保管你数据的服务器。0G 存储网络在保管，Ghast 只是和它对话。
- **不是"云账号"**。没有一个中心账号拥有这些备份。所有权属于签了指针的钱包地址。
